## 1. 范围类型定义

系统存在三种数据范围类型，必须明确定义和处理规则。

### 1.1 范围类型分类

| 类型 | 定义 | 访问规则 | 示例对象 |
|------|------|----------|---------|
| **FACTORY_AREA** | 工厂 + 区域 | `factory == user.factory AND area IN user.areas` | Task, Mapping, Inventory |
| **FACTORY_ONLY** | 仅工厂 | `factory == user.factory` | SimpleBOM, WeeklyPlan, Print Agent |
| **GLOBAL** | 全局共享 | 仅明确授权主体 | 系统配置, 数据字典 |

### 1.2 判断依据

对象属于哪种类型，按以下顺序判断：

1. **业务天然属性**：SimpleBOM 全公司统一 → GLOBAL；周计划按工厂编制 → FACTORY_ONLY
2. **操作颗粒度**：仓库任务按区域配送 → FACTORY_AREA
3. **查询/统计需求**：如果需要按区域独立统计 → FACTORY_AREA
4. **历史追溯要求**：如果删除关联后仍需独立追溯 → 需要快照

### 1.3 实施规则

```sql
-- FACTORY_AREA 类型
WHERE factory = :currentFactory 
  AND delivery_area IN (:currentAreas)

-- FACTORY_ONLY 类型  
WHERE factory = :currentFactory

-- GLOBAL 类型
-- 无范围条件，但入口必须 requireRole(ADMIN) 或等价授权
```

**重要**：不要因为没有区域字段就擅自增加，应按业务决策确定类型。

## 2. 账号管理权限矩阵

### 2.1 基本规则

**子集原则**：分配给目标用户的 Role/Factory/Areas 必须是操作者自身权限的严格子集或相等。

```text
操作者权限 ⊇ 目标权限
```

### 2.2 权限矩阵

| 操作者角色 | 可创建角色 | 可分配工厂 | 可分配区域 | 可修改自己 |
|-----------|-----------|-----------|-----------|-----------|
| **ADMIN** | 全部（含ADMIN） | 全部 | 全部 | 是（需二次确认） |
| **SUB_ADMIN** | 低于ADMIN的角色 | 仅自己工厂 | 仅自己区域子集 | 否（需ADMIN） |
| **其他角色** | 无权限 | 无权限 | 无权限 | 否 |

### 2.3 特殊规则

**ADMIN 保护**：
- 系统至少保留1个启用的ADMIN账号
- 创建/提权为ADMIN需要二次确认
- 最后一个ADMIN禁止禁用或删除
- ADMIN修改自己范围需要二次确认并记录原因

**范围修改**：
- 修改账号范围立即失效该用户所有Session和WebSocket Ticket
- 范围变更必须记录：操作人、目标用户、原范围、新范围、原因、时间
- 禁止账号修改自己的范围（防止提权）

**并发控制**：
- 用户修改使用乐观锁（version字段）
- 范围关联表修改在同一事务内完成
- 失败时整体回滚，不允许部分成功

## 3. 工厂与区域字典

### 3.1 数据库结构

```sql
CREATE TABLE sys_factory (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    factory_code VARCHAR(64) UNIQUE NOT NULL COMMENT '工厂代码：弋江/三山',
    factory_name VARCHAR(200) NOT NULL,
    enabled BOOLEAN DEFAULT true,
    display_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
);

CREATE TABLE sys_delivery_area (
    id BIGINT PRIMARY KEY AUTO_INCREMENT,
    factory_code VARCHAR(64) NOT NULL COMMENT '所属工厂',
    area_code VARCHAR(64) NOT NULL COMMENT '区域代码：YJ-LP/SS-LP/H19等',
    area_name VARCHAR(200) NOT NULL,
    enabled BOOLEAN DEFAULT true,
    display_order INT DEFAULT 0,
    created_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP,
    updated_at TIMESTAMP DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP,
    
    UNIQUE KEY uk_factory_area (factory_code, area_code),
    INDEX idx_factory (factory_code),
    FOREIGN KEY (factory_code) REFERENCES sys_factory(factory_code)
);
```

### 3.2 完整性约束

**服务层校验**：
- 用户分配区域前，校验 `(factory, area)` 在字典中存在且启用
- 创建业务数据前，校验工厂和区域合法性
- 禁止给弋江账号绑定三山区域

**级联处理**：
- 工厂/区域停用后，新数据不能使用该值
- 已有数据保持不变（历史追溯）
- 已有账号绑定保持（但可配置是否自动禁用账号）

**编码规范**：
- 统一大小写（建议全大写或数据库 COLLATE）
- 禁止前后空格
- 历史别名通过映射表维护，不直接修改原值

## 5. 对象归属转移规则

### 5.1 基本原则

**默认禁止修改归属**：普通账号和普通管理员不能修改业务数据的factory/deliveryArea。

### 5.2 管理员转移规则（如需开放）

**前置条件**：
- 只有ADMIN可以跨范围转移
- 转移原因必填
- 需要二次确认
- 转移前后审计

**转移范围**：
```java
public void transferTaskScope(
    String taskNo, 
    String newFactory, 
    String newDeliveryArea,
    String reason
) {
    requireRole(ADMIN);
    Task task = taskRepository.findByTaskNo(taskNo);
    
    // 审计旧值
    auditService.log("SCOPE_TRANSFER_BEFORE", 
        task.getFactory(), task.getDeliveryArea());
    
    // 转移主对象
    task.setFactory(newFactory);
    task.setDeliveryArea(newDeliveryArea);
    taskRepository.save(task);
    
    // 级联处理
    if (task.getPrintJobNo() != null) {
        PrintJob job = printJobRepository.findByPrintJobNo(task.getPrintJobNo());
        if (job != null) {
            job.setFactory(newFactory);
            // deliveryArea 按PrintJob决策确定是否同步
            printJobRepository.save(job);
        }
    }
    
    // 审计新值
    auditService.log("SCOPE_TRANSFER_AFTER", 
        newFactory, newDeliveryArea, reason);
}
```

**禁止转移的情况**：
- 已完成且归档的任务
- 关联对象过多且无法原子性转移
- 跨公司/跨法人实体

**建议**：如无特殊需求，初期不开放归属转移功能，改为：
1. 取消原任务（保留历史）
2. 在新范围重新创建任务

## 6. HTTP状态码与错误码规范

### 6.1 统一策略

| 场景 | HTTP状态码 | 业务错误码 | 响应消息 |
|------|-----------|-----------|---------|
| 未登录 | 401 | UNAUTHORIZED | Token无效或已过期 |
| 登录但无功能权限 | 403 | FORBIDDEN | 当前角色无权执行该操作 |
| 登录但无数据范围 | 403 | FORBIDDEN_SCOPE | 账号范围配置缺失，请联系管理员 |
| 按编号访问其他范围 | **404** | NOT_FOUND | 资源不存在 |
| 批量含越权项 | 403 | FORBIDDEN_BATCH | 批量请求包含无权访问的数据 |
| 机器身份越权 | 403 | FORBIDDEN_AGENT | Agent无权访问该工厂的数据 |

### 6.2 防探测规则

**不泄露资源存在性**：
- taskNo、printJobNo、labelCode 等业务编号访问时统一返回404
- 错误消息不区分"不存在"和"无权限"
- 列表查询只返回有权限的数据，不因存在其他数据而报错

**审计记录**：
- 403错误记录完整的尝试访问信息（用户、资源、操作）
- 404错误只记录请求编号，不记录是否实际存在
- 按用户统计403频率，超过阈值告警（可能的攻击或误操作）

## 7. 滚动发布与兼容窗口

### 7.1 Expand-Contract模式

**Phase 1: Expand（扩展）**
```sql
-- 1.1 增加可空字段
ALTER TABLE sys_user ADD COLUMN factory VARCHAR(64) NULL;

-- 1.2 创建新表
CREATE TABLE sys_user_delivery_area (...);

-- 1.3 创建工厂/区域字典表
CREATE TABLE sys_factory (...);
CREATE TABLE sys_delivery_area (...);
```

**Phase 2: Migrate（迁移）**
- 部署能读写新字段的应用版本
- DataScope校验处于"监控模式"（记录日志但不拒绝）
- 管理员初始化现有账号范围
- 验证新Session包含范围信息

**Phase 3: Contract（收缩）**
- 启用DataScope强制校验
- 批量失效旧Session
- 回填历史数据
- 考虑是否增加NOT NULL约束（需评估历史数据）

### 7.2 多实例滚动发布

**兼容要求**：
- Phase 1-2期间，新旧版本可以同时运行
- 旧版本不读取新字段，新版本兼容NULL值
- Session结构变化后，新旧Session不能混用（需设置Session版本号或全部失效）

**Redis SessionStore注意**：
- Session序列化格式变化时考虑向后兼容
- 或者滚动发布前先清空所有Session
- Redis中的Session key增加版本后缀

### 7.3 回滚边界

| 回滚点 | 应用 | 数据库 | Session | 说明 |
|-------|------|--------|---------|------|
| Phase 1完成前 | 可回滚 | 可回滚（DROP新增列/表） | 不影响 | 无业务影响 |
| Phase 2期间 | 可回滚 | 不回滚Schema | 清空Session | 旧版本忽略新字段 |
| Phase 3后 | 谨慎回滚 | 不回滚 | 清空Session | 需评估业务影响 |

## 8. 异步与旁路入口清单

### 8.1 异步任务DataScope规则

**原则**：异步任务不能依赖HTTP ThreadLocal，必须显式携带范围或以系统身份运行。

### 8.2 检查清单

| 入口类型 | 当前状态 | 改造要求 |
|---------|---------|---------|
| **定时任务** | 未检查 | 以系统身份遍历，每条记录保留原范围 |
| **@Async方法** | 未检查 | 传递RequestContext或显式范围参数 |
| **Outbox重放** | 有Outbox | 重放时恢复原事件范围 |
| **消息队列** | 未使用 | （如有）消息携带范围 |
| **文件下载** | 未检查 | 临时文件名不含其他范围业务编号 |
| **自动补全** | 未检查 | 候选列表按范围过滤 |
| **Excel错误** | 未检查 | 错误报告不泄露其他范围数据 |
| **健康检查** | 已放行 | /actuator/health 无业务数据 |
| **异常消息** | 未检查 | 不在message中包含业务编号 |

### 8.3 缓存键设计

```java
// ❌ 错误：全局缓存键
String key = "tasks:pending";

// ✅ 正确：包含范围的缓存键
String key = String.format("tasks:pending:%s:%s", 
    factory, String.join(",", areas));
```

**缓存失效**：
- 用户范围变化时清空该用户相关缓存
- 缓存内容不能包含超出范围的数据
- 缓存预热必须分范围进行

## 9. 审计与监控规范

### 9.1 审计日志字段（扩展）

```java
public class AuditLog {
    private Long id;
    private String traceId;
    private Long userId;
    private String username;
    private UserRole role;
    private String factory;              // 操作者工厂
    private String deliveryAreas;        // 操作者区域（逗号分隔）
    private String resourceType;         // Task/Mapping/PrintJob等
    private String resourceId;           // taskNo/id等
    private String action;               // CREATE/UPDATE/DELETE/QUERY等
    private String result;               // SUCCESS/FORBIDDEN/ERROR
    private String beforeFactory;        // 范围变更前值
    private String beforeDeliveryArea;   // 范围变更前值
    private String afterFactory;         // 范围变更后值
    private String afterDeliveryArea;    // 范围变更后值
    private String reason;               // 操作原因（转移、修改等）
    private String batchId;              // 批量操作批次号
    private String message;              // 详细信息
    private LocalDateTime createdAt;
}
```

### 9.2 审计规则

**必须审计的操作**：
- 账号范围创建、修改、删除
- 跨范围转移（如开放）
- 批量删除、导出
- 全局清空、维护操作
- 403错误（越权尝试）
- 机器凭据创建、轮换、吊销
- ADMIN提权、最后ADMIN禁用尝试
- Session批量失效

**保存期限**：
- 普通操作日志：90天
- 范围变更审计：365天
- 安全事件（403、凭据等）：永久或至少2年

**访问权限**：
- 审计日志本身按范围隔离（可查询自己范围的操作）
- 安全审计员可查询全局
- 禁止普通管理员删除审计日志

### 9.3 监控指标

| 指标 | 阈值示例 | 告警级别 |
|------|---------|---------|
| 403错误率 | > 1% | Warning |
| 单用户403频率 | > 10次/分钟 | Critical（可能攻击） |
| DataScope查询P95 | > 500ms | Warning |
| 全表扫描次数 | > 0 | Critical |
| Session失效异常 | > 5次/分钟 | Warning |
| 范围配置缺失 | > 0 | Critical（配置错误） |
| Agent认证失败 | > 10次/小时 | Warning |
