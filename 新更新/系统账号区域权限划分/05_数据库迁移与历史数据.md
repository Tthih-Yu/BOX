# 数据库迁移与历史数据

## 1. 基本原则

- MySQL 和 H2 分开维护兼容脚本。
- Schema、索引、历史回填、权限启用分阶段发布。
- 生产结构变更使用明确 Migration，不依赖 `ddl-auto=update`。
- Schema Migration 与历史数据 UPDATE 分离。
- 任何生产写操作前创建并验证当次新备份。
- 索引根据最终真实 SQL 和 `EXPLAIN` 决定，不提前堆叠无依据索引。

## 2. 当前已知 Migration 基础

已有：

```text
V0.9.1__mapping_factory.sql
V0.9.2__task_print_factory.sql
```

已知基础索引：

```text
idx_task_factory_created(factory, created_at)
idx_print_factory_created(factory, created_at)
```

实体存在字段不代表生产数据库一定已执行 Migration，发布前必须检查 `INFORMATION_SCHEMA` 或等价实际结构。

## 3. 账号范围结构

建议新增：

```sql
ALTER TABLE sys_user
  ADD COLUMN factory VARCHAR(64) NULL;
```

并建立多区域关联表：

```text
sys_user_delivery_area
- id / 或联合主键
- user_id
- delivery_area
- UNIQUE(user_id, delivery_area)
- user_id 索引
```

具体 DDL 需根据当前 ORM、数据库命名规范和外键策略生成后在验证环境测试。

## 4. 从属表结构变化

必须先完成 `03_业务归属与权限决策.md`，再决定实际 Migration。

候选对象：

- Inventory：建议 `factory + delivery_area`。
- Box：建议至少 `factory`，deliveryArea 根据业务归属确认。
- Label：建议至少 factory 快照，区域待确认。
- PrintJob：deliveryArea 待确认。
- AGV Job：快照待确认。
- SimpleBomBatch：factory 待确认。
- ProductionPlan：factory / deliveryArea 待确认。
- MaterialDemand / PurchaseRequirement：继承字段或快照待确认。
- ScanLog / Outbox：建议范围快照。

## 5. 组合索引设计

不要仅因为 DataScope 出现就为所有表统一建立同一索引。

先收集最终 SQL，再用 `EXPLAIN` 验证。例如 Task 可能需要评估：

```text
(factory, delivery_area, status, created_at)
(factory, delivery_area, created_at)
(factory, delivery_area, print_generated, status)
```

实际索引顺序根据：

- 等值过滤列；
- `IN` 区域集合；
- status 等可选条件；
- 排序字段；
- 基数；
- 查询频率。

500 万行 SimpleBOM 导入需单独评估批量写入和索引维护成本。

## 6. 历史数据基线

2026-08-26 快照：

```text
Task factory IS NULL      848
PrintJob factory IS NULL  845
```

当时只读候选分析：

- 848 条缺 factory Task 均可按 warehouse_code 命中唯一工厂候选；
- 仍需核对启用状态、物料号、配送区域、地址，不能直接回填；
- 845 条缺 factory PrintJob 中，843 条关联缺 factory Task，2 条未找到 Task。

实施前必须重新统计，不能把这些数字当成生产更新数量。

## 7. 历史回填流程

1. 重新统计 NULL、空串、非法 factory、非法 deliveryArea 和分布。
2. 为 Task 生成候选，不直接 UPDATE。
3. 候选要求关联唯一且关键业务字段一致。
4. 多候选、无候选、只能凭区域猜测的记录进入人工清单。
5. 审批 Task 候选。
6. Task 确认后通过可靠 taskNo 生成 PrintJob 候选。
7. 无对应 Task 的 PrintJob 独立处理。
8. 验证环境演练并核对数量。
9. 生产分批更新。
10. 未确认记录保持 NULL/未归属，只允许 ADMIN 可见。

明确禁止：

```text
delivery_area = 1  => 猜某工厂
LP                 => 猜某工厂
全表直接 UPDATE
```

## 8. 导入数据范围

导入和 Migration 是不同概念，但都必须遵守范围规则。

普通账号：

- 后端强制写入账号可信 factory；
- deliveryArea 必须属于账号允许集合；
- 文件内范围字段不能扩大权限。

管理员：

- 必须明确目标工厂，或从文件解析；
- 解析值必须在合法工厂/区域字典中；
- 批次激活前再次校验。

冲突检测：

```text
只在相同业务范围内计算冲突
```

## 9. 回滚

需要分别准备：

- 应用回滚；
- Schema 回滚；
- 历史数据回填回滚/恢复；
- Session/缓存处理；
- 发布失败后的权限开关策略。

不要在文档中固化未经验证的 DROP/ALTER 回滚语句。最终回滚 SQL 必须在验证环境与当前 Schema 配套演练。
