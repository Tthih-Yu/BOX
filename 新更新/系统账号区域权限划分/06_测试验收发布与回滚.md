# 测试、验收、发布与回滚

## 1. 测试账号与主体

至少准备：

- ADMIN；
- 弋江/H19 单区域账号；
- 弋江/YJ-LP 单区域账号；
- 弋江同工厂多区域账号；
- 三山/SS-LP 账号；
- VIEWER 等只读角色；
- Android 内网/外网；
- 微信小程序；
- 阿里云/WinServer/Linux Worker；
- Print Agent；
- AGV；
- SAP/IMS/PPC 测试身份。

## 2. 认证与账号验收

- [ ] 登录返回正确 factory/deliveryAreas。
- [ ] ADMIN 可为空表示全局。
- [ ] 普通账号无 factory 或无区域时拒绝访问。
- [ ] 修改 Role/factory/areas 后旧 Session 立即失效。
- [ ] 旧 Session 缺少新范围字段时强制重新登录。
- [ ] Redis 多实例下 Session 失效一致。

## 3. 数据隔离测试

列表：

- [ ] 弋江/H19 账号只返回 `factory=弋江 AND deliveryArea=H19`。
- [ ] 不包含弋江其他区域。
- [ ] 不包含三山数据。
- [ ] 多区域账号可见授权集合全部区域。

编号越权：

- [ ] 篡改 taskNo。
- [ ] 篡改 Mapping id。
- [ ] 篡改 printJobNo。
- [ ] 篡改 labelCode / boxCode / warehouseCode 等业务标识。
- [ ] 统一返回预定 403/404 策略，不泄露资源存在性。

批量操作：

- [ ] 一批数据中含越权项时整体拒绝。
- [ ] 不静默跳过越权记录后继续修改其他记录。

## 4. Task / Mapping / PrintJob

Task：

- [ ] 查询、统计、待打印按范围。
- [ ] 取消、接单、拣料、配送、收货、异常、重试不能跨范围。
- [ ] 创建后归属不随 Mapping 修改漂移。

Mapping：

- [ ] 导入、导出、保存、覆盖、区域删除、IDs 删除按范围。
- [ ] 同名 deliveryArea 在不同工厂不会被一起删除。
- [ ] `scope=ALL` 仅 ADMIN。

PrintJob：

- [ ] 列表、补打、取消按范围。
- [ ] Agent 只能领取绑定工厂作业。
- [ ] Agent 不能通过请求体 factory 跨工厂。
- [ ] 回调不能修改其他工厂 PrintJob。

- [ ] 多候选时拒绝。

## 6. 计划、库存和 Dashboard

- [ ] WeeklyPlan 导入不能跨工厂。
- [ ] WeeklyPlan 激活不能跨范围。
- [ ] SimpleBOM 活动批次按最终决策隔离。
- [ ] ProductionPlan/Demand/PurchaseRequirement 不跨范围计算。
- [ ] Inventory 列表和统计按范围。
- [ ] Label/Box/AGV 按最终决策校验。
- [ ] Dashboard 默认首页不显示其他范围统计。
- [ ] BigScreen、物料用量、最新任务、最新扫码、告警均按范围。
- [ ] 普通请求不再通过全表 `findAll()` 后内存过滤完成 DataScope。

## 7. 日志、导出、维护

- [ ] 日志列表按范围。
- [ ] 日志详情不能通过业务编号旁路。
- [ ] 导出与对应列表使用相同 DataScope。
- [ ] 普通管理员清空只作用当前范围。
- [ ] 全局清空需要独立 ADMIN 入口、二次确认、审计。
- [ ] Recovery/DataQuality 对普通用户不泄露全局明细。

## 8. WebSocket / Redis

- [ ] Ticket 带范围。
- [ ] CONNECT 建立可信 Principal。
- [ ] 手工 SUBSCRIBE 未授权 destination 被拒绝。
- [ ] 普通账号收不到其他区域事件。
- [ ] 普通账号收不到其他工厂事件。
- [ ] 公共 `/topic/*` 不再泄露完整业务数据。
- [ ] 用户队列/定向推送正确。
- [ ] Redis 多实例 relay 不串范围。
- [ ] 断线重连后重新使用最新范围，旧 Ticket 不继续生效。

## 9. 性能测试

至少建立改造前后基线：

- Task 列表 P50/P95/P99；
- Task 状态统计；
- Dashboard；
- Mapping 查询、导入、导出；
- SimpleBOM 大文件流式导入；
- PrintJob 领取；
- WebSocket 推送延迟；
- 多用户、多工厂、多区域并发。

必须检查：

- 关键 SQL `EXPLAIN` 使用预期索引；
- 无明显 N+1；
- 不因范围校验出现逐行数据库查询；
- 大批量操作仍可批处理。

3. 部署后端账号链和 DataScope 基础。
4. 部署已经完成范围封堵的业务服务。
5. 验证普通账号与 ADMIN。
6. 部署 Dashboard/日志等旁路封堵。

8. 部署前端。
9. 完成历史候选审批后分批回填。
10. 少量测试账号灰度。

12. 全量上线。

## 12. 上线监控

至少监控：

- 403/404 权限拒绝数量和异常增长；
- 查询耗时 P95/P99；
- 慢 SQL 和全表扫描；
- Session 失效异常；
- WebSocket 连接数和消息量；
- Redis relay 异常；
- Print Agent 认证失败/无可用作业；
- 扫码失败率；
- 业务侧漏单、漏打、统计异常反馈。

## 13. 回滚边界

应用回滚和数据库回滚必须分开决策。

优先原则：

- 代码问题但 Schema 向后兼容：优先回滚应用。
- Schema 问题：按已演练方案处理数据库。
- 历史回填问题：停止后续批次，使用备份/回滚清单恢复，不继续自动猜测修复。
- 权限问题：宁可 fail closed，不通过临时关闭 DataScope 恢复“可用性”。
